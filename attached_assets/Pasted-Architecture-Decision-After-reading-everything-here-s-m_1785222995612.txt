The key insight: The eventBus (in-process EventEmitter) is used for:

Cross-service communication within the pipeline (token:bought → metadata, momentum, projection, holders, image)
SSE-facing events (projection:updated, token:sold, token:deleted, holders:updated, feed:item → SSEGateway)
Lifecycle triggers (price:updated → lifecycle, projection, intelligence)
For multi-process to work, events that cross the process boundary need Redis pub/sub. Specifically:

Worker process emits events → Redis pub/sub → API process SSE Gateway → browsers
For the same-process pipeline, the EventEmitter is perfectly fine.
